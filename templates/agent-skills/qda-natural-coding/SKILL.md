# QDA 自然编码（Open Coding）

本 skill 不依赖 VS Code 扩展命令，直接读写 Markdown 文件，遵守 markdown-qda 的实体契约。

## 前置条件

- 材料文件存在（用户指定，或按 `tags` 块式列表中的 `material` 与目录结构定位）
- 材料段落需要 `^id` 块标识（缺失时按下方规则补上）

## 块 ID 规则（必须遵守）

- 格式：`^xxxxxx`——6 位，字符集 `a-z0-9`，行尾前置一个空格
- 行尾已有 `^id` 时直接复用，绝不叠加第二个
- 新生成的 ID 必须对全文查重，避免文件内冲突

## 块引用格式

- `[[文件名#^id]]`，文件名去扩展名（如 `[[20260810-会议#^wq0cl4]]`）

## 编码文件契约

```yaml
---
tags:
  - code
definition: 一句话定义
---
```

`tags` 一律写成 YAML 块式列表（Obsidian 规范），不得写成 `tags: [code]` 内联数组。

正文 = 块引用列表，每行一个 `[[材料#^id]]`。层级由**父编码**的 `children` 声明（本文件不写指向父的字段），需要归组时交给理论编码或扩展的「加入父实体」命令。

## 步骤

1. 读取材料文件，定位未编码的段落（行尾无 `^id` 且未被任何编码文件引用）
2. 逐段 / 逐主题归纳：为有意义的语义单元生成编码名（贴近材料语言，宁具体勿抽象）
3. 按编码名建立编码文件（写入编码本文件夹；已存在则追加引用并去重）
4. 给被编码的段落补块 ID（遵守规则），把引用写入对应编码文件
5. 完成后报告：新建 / 更新了哪些编码、覆盖了多少段落，列出未编码段落

## 检查清单

- [ ] 每个编码文件 frontmatter 的 `tags` 是块式列表且含 `code`
- [ ] 引用格式正确（去扩展名 + `#^id`）
- [ ] 无重复引用、无叠加块 ID
- [ ] 编码名与 definition 一致，不互相重复
